# Каноническая карта воронки Бэтмэнов

Дата канонизации: 2026-08-05  
Статус: `CONFIRMED_WITH_OPEN_GAPS`  
Область: только воронка Бэтмэнов до передачи собственника в OWNER-контур.

## Назначение

Подготовить и активировать Бэтмэна, выдать ему персональные ссылки, сохранить источник и обеспечить контролируемый переход привлечённого собственника в отдельную воронку собственников.

## Канонический путь

```text
источник найма / рекомендация / контент
→ кандидат Бэтмэна в Кандидаты_HR
→ идентификация через @batman_strateg_bot
→ назначенный Zoom и сообщения HR-Zoom
→ Zoom-click / напоминание / догонялка
→ решение об активации
→ команда «Бэтмен»
→ активация и присвоение btm_id
→ выдача персональной business_test_main
→ команда «Команда» выдаёт персональную hr_invite
→ Бэтмэн приглашает собственника
→ переход собственника с сохранением btm_id как btm_id_referrer
→ отдельный OWNER-контур
```

## Подтверждённые этапы

| Этап | Подтверждённый факт | Основной объект |
|---|---|---|
| Кандидат | HR/Zoom-данные хранятся в `Кандидаты_HR` | кандидат / `HR-*` |
| Telegram-вход | `/start` находит кандидата и отправляет Zoom-сообщение | `telegram_chat_id` |
| Zoom | Работают напоминание, click redirect и догонялка; клик не равен присутствию | выбранный слот |
| Активация | Только команда «Бэтмен» активирует Бэтмэна и выдаёт `business_test_main` | `btm_id` |
| Команда | Команда «Команда» выдаёт ссылку `hr_invite` | `btm_id` |
| Статистика | «Моя статистика» показывает переходы по `business_test_main` | `btm_id` |
| Передача owner | OWNER entry проверяет `btm_id_referrer`, создаёт/повторно использует `owner_id` и выдаёт тестовую ссылку | `owner_id`, `btm_id_referrer` |

Проверенные примеры активации: `HR-0098 → btm_001001`, `HR-0099 → btm_001002`.

## Идентификаторы и роли

- `HR-*` — запись кандидата до активации.
- `btm_id` — идентификатор источника/Бэтмэна.
- `btm_001001+` — подтверждённый диапазон обычных Бэтмэнов HR-воронки.
- `btm_id_referrer` — неизменяемая привязка собственника к источнику после передачи в OWNER-контур.
- Собственнику не присваивается отдельный `btm_id`; для него используется `owner_id`.

## Действующие контуры

- `@batman_strateg_bot` и `AS-BOT__00_MAIN_ROUTER` обслуживают воронку Бэтмэнов.
- HR-Zoom: `AS-HR-ZOOM-MVP__SCHEDULED_ZOOM_EVENTS`, `AS-HR-ZOOM-MVP__03_ZOOM_CLICK_REDIRECT` и подтверждённые reminder/dogon слои.
- `Кандидаты_HR` — кандидат, Telegram, HR/Zoom и активация.
- `Ссылки_Бэтманов` — персональные ссылки по `btm_id` и типу.
- `БизнесТест_Переходы` / статистический слой — переходы по `business_test_main`.

## Граница с воронкой собственников

Передаваемые данные: валидный `btm_id` как `btm_id_referrer`. После входа собственника действует отдельный бот `@Akademya_Strateg_bot`, отдельный OWNER workflow и `owner_id`. Чаты, Telegram credentials и триггеры двух ботов не смешиваются.

## Не подтверждено или требует отдельной карты

- Полная карта всех источников кандидатов и точная конверсия каждого источника.
- Единый подтверждённый статус фактического присутствия на Zoom: click является только кликом.
- Полная расширенная статистика партнёров, филиалов и внутренних ролей.
- Продуктовая модель за пределами передачи собственника.

## Запреты

- Не использовать `/start` для активации Бэтмэна.
- Не выдавать `business_test_main` автоматически после Zoom.
- Не считать Zoom-click посещением.
- Не давать Бэтмэнам доступ к общей базе и данным собственников.
- Не смешивать Batman-бота с OWNER-ботом.
- Не менять рабочие workflow, credentials, webhook URL, листы и колонки без отдельной задачи и разрешения.
- Не переносить отозванную модель четырёх продуктов.
