# Протокол работы с Каркасником

Дата утверждения владельцем: 2026-08-05  
Статус: `CONFIRMED`

## Приоритет источников

1. Решение владельца проекта и свежий подтверждённый отчёт.
2. `ACTIVE_TASK.md` — единственная активная задача.
3. `TASK_STATE.json` — статус и история выполнения.
4. `00_CONTROL/` — контроль, решения и реестры.
5. `02_STABLE_DATA/` — подтверждённые стабильные данные.
6. `STABLE_CONTEXT.md` и `DO_NOT_BREAK.md` — рабочий контекст и запреты.
7. `CODEX_REPORT.md` — доказательные отчёты.
8. Каркасник — структурированная витрина, пока не утверждён перенос конкретного знания.

Более новое подтверждённое решение владельца имеет приоритет над устаревшей записью.

## Цикл задачи

```text
одна активная задача → preflight → контекст → факты/гипотезы/запреты
→ короткий план → backup перед изменением → выполнение → проверка
→ TASK_STATE.json → CODEX_REPORT.md → стабильное решение при подтверждении
→ retrospective → GitHub/Google Drive → терминальный статус
```

После `COMPLETED` или `CANCELLED` задача удаляется из `ACTIVE_TASK.md` и переносится в историю. Незавершённые терминальные состояния остаются для продолжения.

## Перенос знаний

- Подтверждённый отчёт переносится в `02_STABLE_DATA/` только после проверки.
- Стабильное решение отражается в `business/` или `architecture/` после сверки.
- Ошибка переносится в `retrospectives/` и реестр инцидентов.
- Правило из обратной связи переносится в `ai-clone/feedback/`.
- Каркасник не становится параллельным источником истины: его файлы ссылаются на канонические документы.

## Действующая модель

- Воронка Бэтмэнов.
- Воронка собственников.

Модель четырёх продуктов имеет статус `RETRACTED` и не переносится до нового объяснения и отдельного утверждения владельца.
