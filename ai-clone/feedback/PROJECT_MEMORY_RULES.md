# Правила памяти проекта

## [ПОДТВЕРЖДЕНО]

- Всегда одна активная задача.
- Перед задачей читать AGENTS.md и канонические контрольные файлы.
- Свежие решения владельца выше устаревших отчётов.
- Каркасник структурирует знания, но не становится вторым источником истины.
- Секреты, персональные данные и live-конфигурации не помещаются в GitHub или отчёты.
- Документальная реорганизация не должна менять production.
- Отозванная модель четырёх продуктов не переносится как действующее знание.
- После значимого изменения нужны проверка, TASK_STATE и CODEX_REPORT.

## [ОШИБКА, которую предотвращаем]

Нельзя считать наличие файла в каркасе доказательством подтверждённого знания: сначала нужна сверка с владельцем, стабильными данными или доказательным отчётом.
